## 〇、协议总览
| 项 | 定案 |
|----|------|
| 协议 | HTTP/1.1 + TLS（公网强制，局域网可明文但推荐自签 HTTPS）；**不使用 WebSocket**（决策 A-WS1，见 §7.1） |
| 风格 | REST + 少量动作型端点（submit/confirm）；资源名复数 snake_case |
| 版本 | URL 路径版本 `/api/v1`；v1 内只做向后兼容的增补（新增可选字段/端点），破坏性变更升 v2 并行运行 |
| 编码 | 请求/响应 `application/json; charset=utf-8`；字段名 snake_case；枚举一律小写字符串（与 DBD CHECK 一致） |
| 时间 | 时间戳 `"YYYY-MM-DD HH:MM:SS"`（服务器本地时区，D13）；日期 `"YYYY-MM-DD"`；时长一律 `*_ms` 毫秒整数 |
| 鉴权 | `Authorization: Bearer <JWT>`；除 §2.4 白名单外全部端点要求 |
| 文档 | FastAPI 自动生成 OpenAPI（`/docs`），本规范为契约源，schema 实现须与 §5 对齐 |

## 一、通用约定
### 1.1 请求头协议
| 头 | 方向 | 必填 | 说明 |
|----|------|------|------|
| `Authorization` | → | 鉴权端点 | `Bearer <JWT>` |
| `Idempotency-Key` | → | `exam/submit`、`game/submit` | uuid v4；客户端生成，**成功前不得更换**；服务端 24h 去重 |
| `X-Request-ID` | →/← | 否 | 客户端可自带用于日志串联；缺失时中间件生成并回传（全链路追踪） |
| `X-New-Token` | ← | — | 滑动续期（§2.2） |
| `X-Idempotent-Replay` | ← | — | 幂等重放标记（§3.3） |
| `Retry-After` | ← | 429 时 | 秒数 |
| `Content-Disposition` | ← | 导出类 | `attachment; filename="..."` |
### 1.2 响应结构
**成功**：业务数据直接作为顶层 JSON（不包 `success` 壳）；列表类统一分页信封：
```json
{ "items": [...], "total": 4213, "page": 1, "page_size": 50 }
```
游标分页（预留大列表）：`{ "items": [...], "next_cursor": "..." | null }`。
**失败**：统一错误信封，HTTP 状态码语义化：
```json
{
  "code": "QUOTA_EXCEEDED",
  "message": "今日新词额度已用完",
  "detail": [ { "field": "daily_new_limit", "issue": "exhausted" } ]
}
```
`code` 为稳定字符串枚举（§8 完整目录），前端按 code 分支处理，**不得解析 message 文案**；message 仅展示用。
### 1.3 状态码语义表
| 码 | 语义 | 典型场景 |
|----|------|---------|
| 200 | 成功（含幂等重放） | — |
| 201 | 创建成功 | 新建词库/章节/单词 |
| 202 | 已受理（异步） | 大文件导入解析 |
| 204 | 成功无返回体 | logout、blur 上报、删除 |
| 400 | 请求本身非法 | 参数缺失/格式错 |
| 401 | 未认证/凭证失效 | 三种子 code（§2.3） |
| 403 | 已认证但无权限 | 非 admin 访问管理端点 |
| 404 | 资源不存在或非本人（**越权一律 404，不泄露存在性**） | 他人词库 id |
| 409 | 业务状态冲突 | 用户名重复、重复入库、状态机非法迁移 |
| 410 | 资源已过期 | 预览 token 超时 |
| 413 | 文件过大 | >10MB |
| 415 | 类型不支持 | 非白名单扩展名 |
| 422 | 语义校验失败 | 范围越界、行数超限、防作弊判定 |
| 429 | 限流 | 注册 IP 限流 |
| 500 | 服务器内部错误 | — |
| 503 | 暂时不可用 | SQLite 写忙重试耗尽（DB_BUSY） |
### 1.4 强制约定（对应架构红线）
1. **user_id 永不出现在 body/query**；服务端一律取自 JWT `sub`。v3.3 全局中间件：POST/PUT/PATCH body 携带 `user_id` 一律 400 `USER_ID_FORBIDDEN`（devdata 等需指定目标用户的端点用 `target_user_id` 字段）。
2. 服务端时间唯一权威：客户端不得提交 `created_at` 类时间字段（提交类仅允许 `duration_ms` 等相对量，服务端复核）。
3. 越权访问他人资源返回 404（与“不存在”同响应，防枚举）。

## 二、认证与令牌协议
### 2.1 JWT 结构
```json
{
  "sub": "12",           // user_id（字符串化）
  "name": "bob",
  "role": "user",        // user | admin
  "pv": 3,               // pwd_ver（口径16：改密/重置 +1）
  "iat": 1725400000,
  "exp": 1726004800,     // iat + 7天
  "jti": "9f1c..."       // uuid（预留，本期不做黑名单）
}
```
校验顺序：签名 → exp → pv 与 User 表当前值比对 → 账号 is_deleted 检查。失败分别返回：
| 场景 | HTTP/code | 前端行为 |
|------|-----------|---------|
| 无/坏 token | 401 `AUTH_REQUIRED` | 跳登录 B1 |
| 过期 | 401 `AUTH_EXPIRED` | 跳登录 B1（保留目标路由） |
| pv 失配 | 401 `AUTH_PWD_CHANGED` | 提示「密码已变更，请重新登录」 |
| 账号已注销 | 401 `AUTH_DEACTIVATED` | 提示「账号已注销，30 天内可联系管理员恢复」 |
### 2.2 滑动续期协议（D14 落定）
- 服务端在**任意**鉴权请求处理时检查：`exp − now < 24h` → 响应附加 `X-New-Token`（全新 7 天令牌，pv 不变）；
- 前端拦截器原子替换存储的 token；旧 token 自然过期前均有效，在途请求不中断；
- 每令牌仅续期一次的判定：新令牌 `iat` 重置，自然不会连续触发。
### 2.3 登录/锁定协议
`POST /auth/login` 失败一律 `401 {code:"AUTH_INVALID", message:"用户名或密码错误"}`——**连续失败锁定（用户名+IP，5 次/10 分钟）不改变响应**（模块 1 防锁号探测），仅服务端计数与日志记录。成功响应：
```json
{ "token": "...", "user": { "id": 12, "username": "bob", "role": "user" } }
```
### 2.4 免鉴权端点白名单
`POST /auth/register`、`POST /auth/login`、`GET /api/health`、`GET /api/v1/tts`（匿名音频端点，audio 标签无法携带鉴权头）、静态资源。其余全部鉴权。
### 2.5 改密协议（口径 16 完整闭环）
`POST /auth/password {old_password, new_password}` → 服务端：校验旧密码 → bcrypt 存新 → `pwd_ver+1` → **响应签发新 token（含新 pv）**。效果：当前会话无感续用，其余全部设备旧 token 立即 401 `AUTH_PWD_CHANGED`。管理员重置同理（被重置用户所有会话失效）。

## 三、幂等与离线重放协议（D9/D19/口径24 权威定案）
### 3.1 双机制总表
| 机制 | 载体 | 适用端点 | 服务端去重窗口 |
|------|------|---------|--------------|
| 头幂等 | `Idempotency-Key: <uuid>` | `POST /exam/submit`、`POST /game/submit` | 24h（idempotency_record） |
| 体幂等 | `request_id: <uuid>`（body 字段） | `study/self-rate`、`study/dictation`、`practice/answer`、`review/answer` | 24h + `uq_tr_request` 唯一索引兜底 |
### 3.2 服务端行为
1. 首次到达：正常执行 → 响应快照写入 `idempotency_record(key, endpoint, status_code, response_snapshot)`；
2. 重复到达（窗口内）：**不重复执行任何写操作**，返回首次快照；
3. 并发穿透（同 key 同时到达）：由唯一索引捕获，后者读快照返回（DBD §五双层兜底）。
### 3.3 重放响应协议（★ 对 AD/DS 的口径统一）
重放响应：**HTTP 200 + `X-Idempotent-Replay: true` + 首次响应体**。
> 澄清：此前 AD §6.4/DS 6.4 中「409 视为成功」为简写，**以本节为准**——重放统一走 200 + 标记头，客户端无需区分成功与重放，逻辑最简。409 仅保留给真正的业务状态冲突。
### 3.4 客户端（前端）重放协议（D19）
```
队列项：{ request_id, method, url, body, failed_at }
入队：    单题端点网络失败（非 4xx 业务错）→ 入 pending
重放触发：online 事件 ∨ 页面 focus ∨ 30s 兜底定时器
重放规则：按 failed_at 升序串行；Web Locks 互斥（防双标签页并发）
剔除：    2xx（含 X-Idempotent-Replay）→ 剔除
保留：    网络错误 → 保留待下次
放弃：    4xx 业务错（如 QUOTA_EXCEEDED）→ 剔除 + toast「该题未同步成功：额度已用完」
过期：    队列项 >24h → 剔除（服务端窗口已关，重放必失败）
考核例外：exam 全链路不入重放队列（中断即作废，口径22）
```

```
→ 204；paper.status=void，不计成绩不占历史（口径22）
GET /exam/records?page=
→ 分页列表 {id, score, passed, duration, blur_count, config_snapshot, created_at}

GET /exam/records/{id}
```

## 六、限流协议
| 维度 | 规则 | 响应 |
|------|------|------|
| 登录失败锁定 | 用户名+IP，5 次失败/10 分钟 | **不改变响应**（统一 401 AUTH_INVALID，防探测），仅日志 |
| 注册 | IP 10 次/小时 | 429 `RATE_LIMITED` + `Retry-After` |
| Nginx 层 | auth 路径 limit_req burst=10（双保险） | 503（Nginx 默认，可配 429） |
| AI 手动刷新 | 3 次/人/日（D28） | 429 `ADVICE_REFRESH_LIMIT` |
内存计数实现（AD ADR-6），重启清零可接受；响应不含 `X-RateLimit-*` 头（近似值无契约价值）。

## 七、异步通信协议
### 7.1 WebSocket 决策：v1 不引入（A-WS1）
| 候选需求 | 采用方案 | 理由 |
|---------|---------|------|
| 导入解析进度 | 轮询（§7.2） | 解析秒级完成，轮询足够 |
| 考核失焦上报 | fire-and-forget POST | 无需实时下行 |
| 失焦计时/对局同步 | 无（本地权威 + 结算复核） | 防作弊本就要求服务端结算制 |
| 通知/建议推送 | 登录/刷新时拉取 | 每日一次的粒度，无需推送 |
单进程异步架构下 WS 会引入连接管理与心跳复杂度，收益为零；扩展阶段如需（多实例在线状态）再评估。
### 7.2 导入轮询协议
```
间隔：固定 2s（备忘2）；连续轮询上限 150 次（5 分钟）→ 视为 failed，
      前端提示「解析超时，请重试」并释放 job
终止：status ∈ {preview_ready, failed} 即停
竞态：job 属主校验（404）；token 过期与 job 状态独立（410 仅在 preview 接口）
```
