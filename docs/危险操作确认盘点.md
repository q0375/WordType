# 危险操作确认盘点（WordType）

> 2026-10-04 全站扫描结论。判定标准：操作**不可逆 / 丢数据 / 影响他人 / 占用额度或推进排期**即视为需要确认。
> 统一入口：前端破坏性操作一律走 `frontend/src/core/confirm.ts` 的 `confirmAction()`，
> 键盘约定：↑↓←→ 切换按钮高亮、Enter/空格触发高亮项、Esc 取消、**初始焦点在「取消」**（回车不会误触危险动作）；
> `installMessageBoxKeys()`（main.ts 安装）同时给管理端存量 `ElMessageBox.confirm` 补齐键盘导航。

## 三、不需要确认 ➖（低风险/可逆，明确豁免，避免过度弹窗）

- 刷新队列、置顶/取消置顶、昵称修改、设置页保存；
- 管理员口径配置保存（下坠倍数 game_service.py 配套 AdminView.vue:349、考核口径三元组）——覆盖式但立即可再改回，有成功 toast 即可；
- 邀请码批量生成（只增不删，AdminView.vue:568）、班级调整、启用类开关；
- 退出登录（无数据影响）。

## 四、新增操作检查清单（以后加功能时过一遍）

1. 会丢/覆盖用户数据吗？→ 必须 `confirmAction`，文案写明范围与可逆性
2. 会影响**他人**（学生/其他用户）吗？（停用、分配、口径变更）→ 必须确认 + 成功后明示影响面
3. 会消耗不可再生额度或推进排期吗？（复习额度、考核次数、SM-2）→ 建议确认
4. 破坏性弹窗初始焦点必须落在「取消」；键盘可达（confirm.ts 已全局保证）
5. 路由离开/关页面时存在"进行中会话"的，必须加 `onBeforeRouteLeave` 守卫（参照练习/考核模式）
