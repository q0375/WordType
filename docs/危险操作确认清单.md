# 危险操作确认清单（2026-10-03 审计）

> 用途：新增/修改任何会丢数据、中断进行中流程、影响他人的操作时，先对照本清单决定**是否需要二次确认**。
> 统一实现：`frontend/src/core/confirm.ts` 的 `confirmAction()`；键盘导航由 `installMessageBoxKeys()`
> 在 `main.ts` 全局安装，站内所有 MessageBox 都能用 ↑↓←→ 切换 + 高亮、Enter/空格确认、Esc 取消。

## 一、判定标准（满足任一条就要确认）

1. **不可逆**：删除、清空、重置后数据无法找回（或只能靠管理员手工恢复）；
2. **中断进行中的流程**：用户可能已经投入了时间/进度，一���点就没了；
3. **影响他人**：操作作用于他人数据或影响全体用户（停用、注销、清空他人数据）；
4. **高误触成本**：按钮紧挨密集列表、一步点击即生效（如叉叉、图标按钮）。

不需确认：只改本地视图状态的（换其他单元/重学一遍/放弃表单修改）、可一键撤销的轻量开关、提交答案类常规操作。

### 错题本「移出」为何需要确认（2026-10-04 补）

原判定为「常规操作且可自行再添加」是**错的**。`patch_wrongbook(resolved=1)` 直接把词移出在册列表，
**绕过了「连对 3 次自动攻克」的规则**（`stat_ops.touch_wrongbook` 的 `conquer_count >= 3` 判定只在答对时触发）。
用户点错了没有任何补救入口——只能在「已攻克」页签里手动翻找，而该页签默认不展示。
故按「高误触成本」判定为需确认。置顶/取消置顶仍不需确认（可逆、无副作用、且有视图筛选配合）。

## 三、明确判定为「不需要确认」的项（避免过度打扰）

- 学习页「换其他单元」「重学一遍」、设置页「放弃修改」：仅重置本地视图，已答内容已入库；
- 游戏暂停面板「继续游戏 / 重新开始 / 退出游戏」：面板本身即决策容器（Esc 唤出、↑↓ 选择、回车确认），不再叠加二次弹窗；
- 复习页「提前复习」：**不占今日额度、不改SM-2 排期**（2026-09-23 起改为「置顶」语义，`review_advance` 只返回
  `word_ids`，不插队列行、不动 `next_review_at`），未点「开始」就不会产生任何记录，置顶后也只是重排显示顺序
  且刷新即还原 → 无不可逆后果，不需确认。⚠️ 若日后改回「插队并推进排期」的语义，此项须重新评估；
- 错题本「置顶 / 取消置顶」：可逆、无副作用，配合「只看置顶」筛选即可还原；
- 错题本逐题作答提交：单次提交即入库，与练习/复习一致，不需二次确认；
- 管理端批量生成邀请码：prompt 对话框本身就是输入确认容器。
