> 当天已完成生产库"幽灵 inode"抢救 + 更新上线，本包内数据库为抢救后的一致性快照。

## 一、迁移包里有什么

```
wordtype/
├── backend/
│   ├── app/               # 最新后端代码
│   ├── requirements.txt   # 依赖清单（含 edge-tts）
│   ├── .env               # ⚠️ 密钥与配置（见下）
│   ├── data/
│   │   ├── wordtype.db    # ✅ 生产数据库一致性快照（integrity ok：8 用户 / 8040 词 / 25 表）
│   │   └── dicts/ files/ tts_cache/   # 空目录，tts_cache 会自动重建
│   └── backup/            # 历史每日备份
└── frontend/dist/         # 前端构建产物
```

## 二、哪些东西是"命根子"

| 项目 | 位置 | 丢失后果 |
|------|------|----------|
| 生产数据库 | `backend/data/wordtype.db` | 用户、词库、学习记录全没 |
| `JWT_SECRET` | `backend/.env` | 换新 → 所有用户被登出（重新登录即可，不致命） |
| `AES_KEY` | `backend/.env` | 换新 → 用户保存的服务端 AI 凭据解不开（需重新配置） |
| `ADMIN_PASSWORD` | `backend/.env` | 管理员登录凭据 |
| `TZ=Asia/Shanghai` | `backend/.env` | 每日额度/复习调度/定时任务全按这个时区算，**必须保留** |

`.env` 原样带走最省事：用户 token 继续有效、AI 凭据照常解密。

## 三、方案 A：迁到另一台 Linux 服务器（最顺，10 分钟）

```bash
# 1. 基础环境（Ubuntu）
sudo apt-get install -y python3 python3-venv python3-pip nginx

# 2. 解压迁移包
sudo mkdir -p /opt && sudo tar -xzf wordtype-migration-20260917.tar.gz -C /opt
# 得到 /opt/wordtype/{backend,frontend}

# 3. 建虚拟环境装依赖
cd /opt/wordtype/backend
sudo python3 -m venv venv
sudo ./venv/bin/pip install -r requirements.txt

# 4. systemd + nginx（配置文件在仓库 deploy/ 目录，已修复 rsync 事故版）
sudo cp deploy/wordtype.service /etc/systemd/system/
sudo cp deploy/nginx-wordtype.conf /etc/nginx/sites-available/wordtype
sudo ln -sf /etc/nginx/sites-available/wordtype /etc/nginx/sites-enabled/wordtype
sudo rm -f /etc/nginx/sites-enabled/default

# 5. 权限与启动
sudo useradd --system --create-home --shell /usr/sbin/nologin wordtype || true
sudo chown -R wordtype:wordtype /opt/wordtype
sudo systemctl daemon-reload && sudo systemctl enable --now wordtype
sudo nginx -t && sudo systemctl reload nginx
```

启动时 `init_db` 会自动校验表结构（缺列自动补），无需手工迁移。

## 四、方案 B：跑在自己的 Windows 机器上（本机就是开发环境）

1. **解压迁移包**到任意目录，比如 `C:\wordtype`。
2. **换库**：把 `wordtype/backend/data/wordtype.db` 覆盖到项目的 `backend/data/`。
   ⚠️ 本机现有 `D:\test\encn\backend\data\wordtype.db` 是**开发测试库**，先改名备份，别和生产库搞混。
3. **用服务器的 .env**（保持密钥一致，用户无需重新登录）。后端代码直接用本仓库 `D:\test\encn\backend`。
4. **启动后端**（本机 .venv 已就绪）：
   ```powershell
   cd D:\test\encn\backend
   .venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
5. **前端两种跑法**：
   - 少数人用：直接 `npm run dev`（5173 端口，已配置 API 代理），最省事；
   - 正式一点：`frontend/dist` 已是现成构建，用 Caddy（单 exe）托管：
     ```
     :80 {
         handle /api/* {
             reverse_proxy 127.0.0.1:8000
         }
         handle {
             root * C:/wordtype/frontend/dist
             try_files {path} /index.html
             file_server
         }
     }
     ```
     （或用 nginx for Windows，改一下 `root` 路径即可）
6. **防火墙**放行 80/8000；局域网用户访问 `http://<你的内网IP>/`。
7. **开机自启**：任务计划程序建"开机启动"任务跑启动脚本，或用 nssm 注册为 Windows 服务。

## 五、没有公网 IP 怎么对外

- **只在局域网/家里用**：什么都不用做。
- **要外网访问**：
  - Tailscale（最简单）：所有设备装客户端组虚拟局域网，访问 `http://100.x.x.x/`；
  - frp：需要一台有公网 IP 的跳板机转发；
  - Cloudflare Tunnel：免费，需要一个域名。
- 服务器到期前把新地址通知使用者即可（现在大家用的是 `http://106.53.199.114/`，没有域名）。
