## 一、选题背景及意义

### 1.1 选题背景

#### 1.1.1 词汇记忆是外语学习与语言能力形成的核心瓶颈

词汇量是衡量语言学习者语言水平的基础性指标。以我国大学英语四级考试为例，其考试大纲要求掌握的词汇量约为 4500 词；即便母语者阅读能力正常，其可用词汇量也在数万量级。词汇学习与阅读、听力、口语、写作四项技能高度耦合：阅读理解速度直接受制于高频词的识别速度（读者对非熟练词的处理时间可达熟练词的 4～7 倍），听力理解则要求对连续语流中的目标词进行快速形码还原。因此，词汇记忆效率是影响外语学习整体效率的关键变量。

然而，长期以来词汇学习在实践中呈现出"投入高、见效慢、易放弃"的特征。大量学习者在单词书或背单词 App 上反复投入，却始终难以形成稳定的长期记忆，其学习行为通常陷入三类循环：

1. **低效重复循环**：习惯于"看着答案读一遍就算记住"，缺乏对记忆强度的客观检验，学习过程停留在"再认"（recognition）而非"回忆"（recall）水平；
2. **无计划循环**：或长期不复习导致遗忘，或在考前突击导致"短期会、长期忘"；
3. **无反馈循环**：学习者无法直观感知自己的记忆状态与薄弱环节，只能凭主观感觉判断进展，一旦感觉失效便放弃。

这三类循环的共同根源在于：**学习过程本身是"黑箱"的**——学习者投入了时间与努力，却无法获得关于"记忆发生了什么、哪些词仍未稳固、下一步该怎么练"的即时反馈。

#### 1.1.2 记忆科学已为"如何有效复习"提供了明确答案

遗忘规律的研究已有一百余年历史。艾宾浩斯（H. Ebbinghaus，1885）通过无意义音节的实验描述了遗忘的进程，提出"先快后慢"的遗忘曲线，这一结论至今仍是设计复习系统的经验基础。但近三十年的研究对艾宾浩斯的结论作了重要修正与细化：

- 间隔效应（spacing effect）与提取练习（retrieval practice）是长期保持的核心机制。 Cepeda 等人（2006）对分布式练习（distributed practice）的元分析表明，复习间隔的合理安排对 verbal recall 成绩有显著主效应；Roediger 与 Karpicke（2006）证明单纯的"反复学习/重读"虽有短期表现优势，却在长期保持上显著劣于"反复提取"；Karpicke 与 Roediger（2008）进一步指出，被试在经历提取失败后再次学习，其长期保持效果反而优于提取成功，说明**适度困难与反馈纠正（desirable difficulties）本身即为学习增效机制**。
- 元认知是记忆调控的核心。 Bjork（1992）指出，元记忆能力（对自身记忆状态的判断）决定了学习者能否自发安排合理复习；Bjork & Bjork（2011）将这一观点扩展为"合意困难"原则——刻意增加学习难度（如延迟回忆、分散练习、干扰练习）能显著提高长期保持。
- 学习技术存在有效性差异。 Dunlosky 等人（2013）对十类常见学习技术进行了系统评估，给出实践效力的分级结论，其中"练习测试"（含分散练习与自我测试）被评为高效；这一结论为"本系统应以提取练习与间隔调度为核心，而非以内容呈现时长或娱乐化设计为核心"提供了直接依据。
- 词汇学习需要编码策略而非机械重复。 高成效的词汇学习包含"注意（attention）、检索（retrieval）、反应（reaction）、复述（repetition）、语境（contextualization）"等环节；在外语词汇的记忆中，关键词联记法（keyword mnemonic，见 Atkinson & Hilgard《Mnemotechnics》，Royle 对外语词汇的应用）表明，将陌生词与熟悉的心理表象建立联想联结，比机械重复具有更好的保持效果。

这意味着：词汇记忆效率的提升在理论上是有路径可循的，但现有学习工具对这套科学规律的工程化实现普遍不够充分**——这正是本课题的切入点。

#### 1.1.3 数字化学习工具普及，但"科学规律"与"工程落地"之间仍有落差

移动终端与 Web 技术已使学习工具的形态发生根本变化。以多邻国、百词斩、扇贝单词、墨墨背单词等为代表的商业产品已将间隔重复算法引入日常词汇学习，Anki 等开源工具则以 SM-2（SuperMemo 2）算法为社区用户提供可定制的间隔调度能力，客观上完成了记忆科学的大众化传播。

但从研究与工程的视角看，现有实现仍存在若干共性不足：

- 调度算法多为"黑箱"。学习者无法理解排期依据，难以信任与调校算法；
- 反馈多为二元判定（对或错），学习者难以获知"错在哪里、错了多少"，模糊反馈（近/模糊/模糊但可辨）的作用在工程上很少被实现；
- **打字训练与词汇记忆长期割裂**，二者分别由输入练习类软件与背单词类软件承担，用户的操作技能训练无法为记忆巩固服务，记忆训练也无法同时改善键盘输入这一高频信息输入通道的效率；
- 过程性数据未被用于学习干预：用户在何时、何地、以何种节奏作答，产生了大量可用于诊断学习状态的数据，但几乎没有被采集与分析；
- 面向教学组织的过程性度量缺失：教师与教学管理者关注的是"这个班的整体掌握情况如何、谁掉队了、考核是否有过程异常"，现有产品面向个人自我管理，缺少组织层面的度量与干预工具。

#### 1.1.4 课题的提出

本课题拟设计并实现一个"记忆强化助记系统"（WordType），其基本思路是：

> **以记忆科学（间隔效应、提取练习、合意困难）为设计依据，以打字这一高频操作技能为记忆的载体与练习形式，以游戏化反馈为持续激励，以过程性数据为度量与干预依据，构建"学习—练习—测试—考核—游戏化强化—统计复盘"的全闭环助记系统。**

系统已在真实云服务器环境完成部署并投入使用，形成了可运行的完整业务闭环与可验证的口径体系，为本设计的实现可行性与效果有效性提供了直接支撑。

### 1.2 研究意义

#### 1.2.1 理论意义

1. **对记忆科学理论的一次工程化验证。** 本系统将间隔重复调度、提取练习、合意困难三类理论机制，落实为可运行的服务端算法（如基于 SM-2 改造的间隔调度与熟练度生命周期管理），并通过"熟练度—间隔—队列优先级"的量化模型将抽象理论转化为可观测指标，提供了理论落地于具体信息系统的一例工程实现。
2. **对"量化反馈优于二元反馈"的实践检验。** 学习反馈是二元的（对/错）还是连续的（部分正确度、得分比），在以往工具中极少有明确对照的实证对比。本系统在考核与游戏场景中引入基于编辑距离与序列相似度的连续得分比，在学习与练习场景中保留"近/模糊"的模糊反馈，构成一组天然的对照实验设计，可用于检验"反馈粒度"对学习行为与记忆保持的影响，具有理论检验价值。
3. **对"操作技能与言语记忆耦合"这一假设的探索。** 打字并非纯粹的符号录入动作，它包含字符识别（视觉）、字形编码（正字法加工）、手部运动（运动程序）与语义提取（词汇语义）多个环节的多通道加工。心理学与教育心理学中关于打字技能与拼写能力、阅读流畅度之间关联的研究（以 Fischer 关于打字与正字法技能的一系列工作为代表），以及"文字作为思维工具"的认知观点，均提示书写/输入方式会参与语言能力的塑造。本设计将打字作为记忆练习的载体而非独立技能训练，正是对这一假设的一次系统探索。
4. **对过程性数据在个性化学习中的作用提供案例。** 本系统采集并分析了逐词的按键日志、反应时、失焦次数、复习轮次等过程性数据，并据此生成学习建议，为"细粒度过程数据如何支持学习干预"提供了可参考的工程路径。

#### 1.2.2 实践意义

1. **对学习者：降低记忆管理的认知负担，提升单位时间记忆收益。** 学习者不再需要自行制定复习计划，系统自动排出最优复习队列并可视化呈现"哪些词逾期、哪些词高危、哪些词已稳固"，使有限的学习时间优先投入到最需要巩固的内容上。
2. **对学习者：提供可信的、可解释的过程反馈。** 通过打字速度（WPM）、准确率、连续正确数（Combo）、熟练度等级、错题攻克计数等可量化指标，将"我到底记住了多少"从主观感受转化为客观数据，增强学习的掌控感与坚持动机。
3. **对教师与教学管理者：提供组织层面的过程性度量与干预能力。** 通过班级考核、限时组卷、失焦统计、成绩分布与题目/知识点掌握度统计，使教学者能够识别共性薄弱环节与个别掉队学生，实现针对性干预。
4. **对同类产品：提供可复用的设计经验。** 本系统在"双端判定一致性保障""模糊反馈与量化反馈的分场景取舍""游戏化与学习目标的耦合设计""防作弊与服务端权威记账"等方面形成了可迁移的工程经验。
5. **对运动与认知的交叉应用提供延伸可能。** 近年关于运动干预对执行功能与记忆促进作用的研究（如 Hillman、Erickson 与 Kramer 的相关综述）提示，身体活动状态与认知表现存在关联。本系统中的限时模式、节奏压力、失败后即时重试等游戏化机制，在设计与实现层面为后续"运动—认知"类功能预留了扩展空间。

## 二、国内外研究现状

本节围绕本课题所依托的四条技术主线——**记忆规律与复习调度、提取练习与学习技术、词汇记忆编码策略、打字与字形/语言能力**——梳理国内外研究进展，并在此基础上指出现有研究的不足与本课题的切入点。

### 2.1 遗忘规律与间隔重复调度研究

遗忘曲线的研究起源于艾宾浩斯的实验心理学传统，其后经 Bjork（1992）的元记忆理论、Bjork & Bjork（2011）的"合意困难"框架得到系统化发展。在工程实现层面，间隔重复算法的核心模型是 SuperMemo 2（SM-2）算法：由 P. A. Wozniak 在 SuperMemo 系统中提出并描述，通过为每张"卡片"维护"难度因子（ease factor）"与"当前复习间隔（interval）"，在每次复习评价后自适应地推算下一次复习时间，其本质是**以作答正确性为反馈信号、以时间间隔为调控变量的在线自适应调度策略**。

围绕该模型的改进研究主要沿三条路径：

1. **模型参数与规则的修正**：针对 SM-2 难度因子更新过于简单、间隔增长缺乏上限控制、遗忘词处理粗糙等问题，后续研究提出了各自的修正规则；
2. **队列组织与优先级研究**：将遗忘程度、词频、难度、学习者整体进度纳入统一调度，形成"优先复习最需要复习的词"的队列机制；
3. **调度目标的重定义**：将调度目标由"最小化单次复习成本"扩展为"最大化长期记忆保持率"，并逐步纳入"学习者可用时间"作为约束。

在工程产品侧，Anki 以 SM-2 为基础并开放调度算法配置，形成了全球最大的间隔重复用户社区；多邻国等商业产品则将其内置为不可见的调度内核。这些实践在方法普及层面贡献巨大，但其算法细节多为商业机密，学术界与使用者难以据此进行复现、验证与调校。

### 2.2 提取练习、测试效应与学习技术有效性研究

"学习是否应当反复呈现材料，还是应当反复尝试回忆材料"是本世纪记忆研究最重要的转折之一。

- Roediger 与 Karpicke（2006）通过实验证明，提取练习（practice testing）相对重读（restudy）带来更优的长期保持；即使提取正确率在初学阶段较低（提示"合意困难"的典型表现），其长期效果仍显著占优。
- Karpicke 与 Roediger（2008）表明，提取失败后由测试给出的反馈进行再次学习，其保持效果优于单纯的提取成功，说明**错误的提取 + 正确的反馈同样产生学习增量**，这为"错题即学习机会"的产品理念提供了心理学依据。
- Dunlosky 等人（2013）对十类学习技术进行了效能评估，"练习测试"被评为高效技术，Rohrer 的间隔数学练习研究亦支持分散练习的长效优势，为"以提取练习为主干"的产品路线提供了系统性依据。

上述研究对学习工具设计的直接启示是：**产品的主要价值应体现在"让学习者持续进行有效的提取练习并获得反馈"，而不是"让学习者更舒服地浏览内容"**。本设计的整体功能优先级（复习与提取练习为核心、内容呈现为辅）正是基于这一结论。

### 2.3 词汇记忆的编码策略研究

外语词汇记忆研究积累了较为成熟的教学与策略成果：

- **注意与深加工**：深加工策略（deep processing，如词义联想、语境嵌入、例句理解）优于表层加工（机械重复、机械抄写），这一点在 Nation（2013）中被反复强调；
- **双编码与多媒体效应**：Paivio 的双编码理论指出，信息的视觉—语言双重编码比单一通道编码具有更好的保持与提取效果；在教学实践中，配图、例句、发音与词形的多模态呈现被广泛采用；
- **关键词联记法**：以 Rothwell 的关键音（keyword sound）与 Atkinson & Hilgard 的记忆术传统为基础，经 Royle 等人发展出适用于外语生词—熟悉词的联记流程，核心机制是以心理表象的中介联结替代直接的形音联想障碍；
- **语块化与词族策略**：以词根词缀、词族、搭配语块为单位组织学习，可显著降低记忆负荷。

上述成果构成了本系统"题型多样化"（默写、选择、听音、挖空四种题型）与"内容多模态呈现"（词形、音标、例句、发音）的设计依据。

### 2.4 打字输入与字形、拼写及阅读能力的关系

关于"打字/书写这一动作与语言能力关系"的研究，跨越了心理学与教育学两个领域，其核心观点可归纳为三点：

1. **打字是一种多通道加工活动**：它同时包含视觉字符识别、正字法加工（把字母组合映射为词）、手部运动执行与语义提取，因而并非单纯的机械动作；
2. **打字熟练度与拼写、阅读流畅度之间存在关联**：以 Fischer 关于打字技能对正字法技能与阅读流畅度影响的系列研究为代表，实证结果显示打字训练不能简单等同于提升阅读能力，但其对字形—语音映射的建立具有独特作用，尤其在小学阶段的教育干预中被广泛采用；
3. **文字作为认知工具**：以 Gentner 的"语言—思维工具假说"（language of thought hypothesis）为代表的观点认为，书写与阅读能力的获得会反过来重塑个体的语言加工方式。**输入方式（手写 vs 打字）因此并非完全中立的操作细节，而是可能参与认知能力形成的变量。**

**对词汇学习而言，这一线索的意义尚未被充分应用**：输入法的打字练习与词汇记忆分属不同类别的软件产品，二者长期割裂。本课题将二者耦合，把"能把词准确、快速地敲出来"作为记忆巩固的行为标志之一，是对该研究线索的一次直接应用。

### 2.5 自适应学习系统、移动学习与游戏化研究

在信息系统层面，自适应学习系统（Intelligent Tutoring System, ITS）长期致力于根据学习者的实时状态调整内容与难度；移动学习（m-learning）研究则关注碎片化场景下的学习行为组织。二者的交集指向同一问题：**如何在资源受限、时间碎片的学习情境中，把有限时间分配给记忆收益最大化的内容。**

游戏化研究则关注如何借助反馈机制、目标结构、情境压力提升持续投入。相关研究在多个场合得出了一致的警示性结论：**游戏化机制若与学习目标脱钩，会产生"高分低学"甚至反向损害学习效果的后果**；有效的游戏化必须使游戏目标与学习目标在机制层面同构（例如：以打字准确率与速度作为游戏得分，而非以点击次数、运气等与学习无关的因素决定胜负）。这正是本系统"游戏服务于记忆、以服务端复核记账保证积分可信"这一设计原则的来源。

### 2.6 国内研究现状

在国内，相关研究呈现三个主要方向：

1. **多媒体词汇教学与双编码应用研究**：将图像、例句、音频与词形联合呈现以提升记忆效率，是国内英语教学研究与教学实践中最普遍的取向，相关实证研究数量庞大；
2. **记忆方法本土化研究**：联想记忆法、谐音记忆法、归类记忆法、艾宾浩斯复习节点法等在中国学习者中有广泛的应用基础与本土化改良，相关研究多为教学经验总结型，实证设计与量化分析相对薄弱；
3. **移动学习与数字化词汇工具的应用研究**：以中国大学英语四、六级备考为场景，对各类背词 App 的使用效果、影响因素与评价体系开展了较多实证工作，但研究对象多为"整类产品"而非"具体算法机制"，研究问题多聚焦于接受度与使用行为，较少深入到间隔调度、反馈粒度等实现细节。

在产业侧，国内词汇记忆类产品在用户规模、词库规模与游戏化设计上积累充分，并形成了对外语学习的显著正向效应（主要体现为备考通过率与词汇测试成绩的提升）。但在教学组织支持层面，此类产品的共同取向是**面向个人自学**，对班级考核、过程性度量、教学干预的支持相对薄弱。

### 2.7 研究现状小结与本课题的切入点

综合国内外研究现状，可以梳理出如下判断：

| 维度      | 已有研究/产品提供的                       | 尚存不足                          |
| ------- | -------------------------------- | ----------------------------- |
| 记忆规律应用  | 间隔效应、测试效应等规律已被确认；SM-2 类算法已在产品中普及 | 算法黑箱、不可解释、不可调校；参数规则缺少公开验证     |
| 学习反馈    | 产品普遍提供对/错二元判定                    | 部分正确度、模糊反馈的作用未被工程化实现与验证       |
| 技能—记忆耦合 | 打字训练与阅读/拼写关系已有实证研究               | 打字训练与词汇记忆在产品层面仍割裂，未形成闭环       |
| 过程性数据   | 已有逐词正确率、反应时等采集实践                 | 数据未被用于学习诊断与干预建议               |
| 组织层面度量  | 传统考试可提供结果性分数                     | 缺乏过程性度量（异常作答、切屏、群体掌握度分布）的系统工具 |

本课题的切入点由此确立：设计并实现一个以记忆科学为依据、以打字为载体、以游戏化为激励、以过程性数据为度量干预的完整助记系统，并在其中对"反馈粒度""调度可解释性""技能—记忆耦合""过程性数据干预"四项问题给出工程化答案。**

## 三、初步设想及拟解决的问题

### 3.1 系统定位与总体目标

**系统定位**：面向外语学习者与教学组织的一体化记忆强化助记系统，以"让学习者以最低的意志成本维持长期记忆"为设计目标。

**总体目标**：

1. **记忆效率目标**：以间隔重复调度 + 提取练习为核心机制，使学习者单位时间投入获得可观测的记忆保持收益；
2. **反馈质量目标**：以连续量化反馈替代单一二元反馈，并保留模糊反馈的学习宽容度；
3. **激励持续目标**：以与学习目标同构的游戏化机制维持长期坚持动机；
4. **度量可信目标**：以服务端权威记账与过程性数据采集，为学习者、教师与管理者提供可信的过程度量。

### 3.2 需求分析与功能模块

结合记忆学习规律与真实使用场景，本系统划分为九个功能模块：

| 模块        | 核心功能                                                      | 设计依据                     |
| --------- | --------------------------------------------------------- | ------------------------ |
| 认证与账号     | 注册（邀请码制）、登录、令牌滑动续期、密码版本失效、账号注销与数据导出                       | 教学组织下的账号可回收与数据可携出        |
| 词库与章节     | 词库 CRUD、公共/私有词库、章节管理、多格式导入（CSV/TXT/XLSX）、克隆导出、按词量或单元数重分单元 | 记忆的最小组织单元是"词"，需支持按教学大纲组织 |
| 学习（学）     | 自评卡（会/模糊/不会）、默写卡三态判定、续学位置记录                               | 深加工与及时检索反馈（提取练习）         |
| 练习（练）     | 默写、选择、听音、挖空四种题型，断点续练，离线重放                                 | 编码策略多样性（双编码、多通道）         |
| 复习（复习）    | 基于熟练度与间隔的每日队列全量物化、三层优先级（逾期/高危/巩固）、当日答错重现、复习排期日历           | 间隔效应 + 合意困难              |
| 考核（测）     | 限时组卷（可跨多章节）、档位化倒计时、计分口径独立于时限口径、失焦统计、幂等交卷、中断作废、全屏与失焦检测     | 组织层面的结果度量 + 过程异常监控       |
| 游戏（强化）    | Canvas 实时下坠打字、连击阶梯、限时模式、生命值、章节集合分组排行榜、服务端复核计分             | 激励持续 + 与学习目标同构的游戏化       |
| 错题本（闭环）   | 真错自动收录、连对攻克计数、置顶、手动移入移出                                   | "提取失败 + 反馈"同样产生学习增量      |
| 统计与建议（复盘） | 打卡热力图、熟练度分布、打字速度与准确率趋势、未来复习量预测、规则引擎 + 可选大模型的学习建议          | 元认知支持与过程性数据干预            |

### 3.3 关键技术设计要点

#### 3.3.1 记忆调度与熟练度生命周期

系统以 SM-2 的"难度因子 + 间隔"双变量框架为骨架，但按实际教学语义作了改造：

- **间隔推进**：答对时按 `3 天`（间隔≤1 天）或 `间隔 × 难度因子`（四舍五入）推进；答"近似"时按间隔折半；答错时重置为 1 天；
- **难度因子**：答对 +0.05（上限 3.0）、答近似 −0.1、答错 −0.2（下限 1.3），并以数据库约束保证取值范围合法；
- **熟练度增量**：答对时 `+10 × min(连对次数+1, 3)`（连对后增量封顶，避免熟练度虚高），答近似 −12，答错 −25，熟练度上限 100；
- **熟练度生命周期（关键改造）**：熟练度 ≥ 80 的"毕业词"自动退出排期（不再进入复习队列），但**一旦后续答错则立即重新排期**——这一点与经典 SM-2"以复习次数为唯一依据"的思路不同，理由是熟练度在本系统中同时承担了"记忆状态"与"是否需要排期"两个语义，必须允许状态回退。

#### 3.3.2 复习队列的三层优先级与幂等物化

每日复习队列**全量物化**所有已学词（不再设置每日新词上限），并按 SQL 内部分层排序：

- **tier 0 逾期（overdue）**：`下次复习日期 < 今天`，逾期天数越久越靠前；
- **tier 1 高危（danger）**：熟练度 < 40；
- **tier 2 巩固（consolidating）**：其余（含已毕业词，排至队尾）。

该设计的两个工程要点：① 用"唯一索引 + NOT EXISTS"双保险实现**幂等可重入**，替代脆弱的"每日定时跑批"设计；② 队列随日期天然隔离，无需显式清理。

#### 3.3.3 判定与计分的双口径设计

系统按场景采用两套判定口径，这是本设计中最具工程含量的部分：

- **三档模糊判定**（用于学习、练习、复习）：仅去除首尾空白，**区分大小写**，允许容差为 1 的编辑距离误判，输出"正确 / 近似 / 错误"。保留模糊反馈是因为在提取练习中出现少量错误正是"合意困难"的必要条件。
- **连续得分比**（用于考核、游戏）：采用序列相似度算法（`difflib.SequenceMatcher(autojunk=False)`，即 2×最长匹配块覆盖长度÷两串长度之和），区分大小写、空格参与，得到 0～1 的连续得分比。

**双端一致性保障**：后端为 Python、前端为 TypeScript，跨语言无法共享代码，系统实现了**逐位等价的双端复刻**（包括 `SequenceMatcher` 的 b2j 匹配表构造、`find_longest_match`、相邻匹配块合并等内部流程），并配套对拍脚本（judge / game 两套同步校验脚本）在改动后自动比对两端实现输出，防止"前端判对、后端判错"的错位。这是本设计解决的一个真实工程难题。

**计分与时限解耦**：考核的档位设置（宽松/标准/紧凑）仅改变倒计时长度（系数 1.5 / 1.0 / 0.7，下限 3 秒），**卷面分权重始终使用基准时限**，从而保证"同一份卷子无论选择哪一档限时，分数可比、难度可控"，避免限时干预污染难度测量结果。

#### 3.3.4 游戏化机制的同构设计与防作弊


- **得分公式**：`单词得分 = 上取整(得分比 × 该词时限 × 连击倍率)`，连击倍率在连续答对 5/10/15/20 词时阶梯提升至 1.5/2.0/2.5/3.0；漏词扣分 = `上取整((1−得分比) × 时限)`；血量按 `(1−得分比) × 100` 扣减（上限 500）；
- **难度差异体现为同屏词数与生成节奏**（简单/普通/困难分别为 2/3/4 词同屏、生成间隔 3400/2400/1600 毫秒），而非简单地修改倍率，保证同一套计分公式在全难度下成立；
- **限时模式**：总时长 3 分钟，到时后剩余生命 1:1 计入总分，使"生存"与"得分"形成权衡，杜绝无止境刷分；
- **服务端权威**：客户端上报的成绩不被直接采信，服务端**依据逐词日志重算分数与血量**，并与客户端分偏差超过 5% 时以服务端为准；开局时对词池与章节集合做快照并在结算时回写，杜绝伪造分组刷榜；半进位取整规则在两端显式对齐（Python 内置 `round` 为银行家舍入，会与 JavaScript `Math.round` 产生 ±1 漂移）。

#### 3.3.5 其他工程设计要点

- **双端判定、服务端计分**：前端同算法预判定保证 0 毫秒交互体验，所有计分一律以服务端结果为准；
- **一切写操作幂等**：考核交卷与游戏结算采用"头幂等"（24 小时去重），单题作答采用"体幂等"（`request_id`），避免弱网重试导致重复计分；
- **增量式熟练度更新**：以 `UPDATE ... SET proficiency = MIN(100, proficiency + delta)` 形式更新，天然规避读—改—写的并发竞态；
- **时间单一源头**：所有日期字段由服务端下发，规避客户端时区与时钟篡改；
- **安全基线**：密码 bcrypt 存储，JWT 令牌带密码版本号与滑动续期，用户自有大模型凭据以 AES-GCM 加密存储，公网部署时若检测到默认密钥则拒绝启动。

### 3.4 拟解决的主要问题

本设计需要解决的关键问题及其对应方案与预期结果如下。

**问题一：记忆过程不可观测，学习者与教学者都难以判断"记忆到了什么程度"。**
- **问题描述**：现有学习工具的反馈集中于"对/错"，学习者无法判断自己是在"刚好想起"还是"想了很久才想起"，教师更无法在结果性分数之外看到过程异常（如切屏、异常用时、逐题反应时分布）。
- **解决思路**：① 采集逐词的过程性数据（首键时间、按键日志、正确率、反应时、复习轮次、失焦次数），落库为打字流水与逐日活跃度两类记录；② 构建以"熟练度（0～100）"为核心的量化记忆状态模型；③ 以热力图、熟练度分布、速度与准确率趋势、逾期天数分布四种可视化形态呈现记忆全景；④ 生成可执行的学习建议（规则引擎为主，大模型为可选增强）。
- **预期结果**：学习者能够清晰回答"我现在记住了多少、接下来该练什么"；教学者能够获得班级层面的掌握度分布与过程异常清单，定位共性薄弱点与个别掉队者。

**问题二：复习调度与遗忘规律的对接不够精细，且算法对学习者不可解释。**
- **问题描述**：SM-2 的原始形式以"复习次数"为唯一状态，间隔增长缺少上限约束，遗忘词的处理过于粗糙；同时算法内部状态对使用者不可见，一旦排期与主观感受不符便难以信任。
- **解决思路**：① 以"熟练度 + 难度因子 + 间隔 + 下次复习日期"四元组重构记忆状态，引入毕业与回退机制（掌握退出排期，遗忘即刻回队）；② 对难度因子施加数据库取值约束以保证合法性；③ 队列采用"逾期 / 高危 / 巩固"三层优先级显式分层，排序规则透明且可解释；④ 提供"未来 N 天复习量预测"与"复习排期日历"，使调度结果对学习者可见。
- **预期结果**：调度结果可解释、可预测、可调校；复习时间优先投向最易遗忘与最薄弱的词，避免"已掌握词反复占用时间"与"薄弱词长期遗漏"两类资源错配。

**问题三：同一学习行为在不同场景下的判定标准难以统一，双语言实现易出现错位。**
- **问题描述**：同一套判定逻辑需要在后端（Python）与前端（TypeScript）各实现一次，用于保证零延迟的前端预判定。跨语言复刻存在大量隐性差异（编辑距离的提前退出条件、序列相似度的匹配块合并、空格与大小写处理），一旦漂移即出现"界面显示正确但服务端记错分"的不一致，且此类缺陷隐蔽、难以发现。
- **解决思路**：① 将判定逻辑定义为"纯函数 + 集中口径"（所有默认值与阈值集中于唯一配置文件，其余模块一律引用，禁止就地写字面量）；② 前端对后端算法逐位等价复刻，包括其内部匹配表构造与匹配块合并流程；③ 编写跨语言对拍脚本，在改动后自动比对两端对同一批样本输入的输出，差异即失败；④ 按场景区分口径：学习类场景用容差 1 的三档模糊判定（保留"合意困难"），考核类场景用连续得分比（严格量化）。
- **预期结果**：双端判定结果可自动验证一致；口径变更经单一入口 + 对拍校验，消除了"改了一处漏了一处"导致的口径错位。

**问题四：游戏化若与学习目标脱钩，会产生"高分低学"甚至反向损害学习效果的风险。**
- **问题描述**：常见做法以点击次数、运气、连续登录天数等与学习无关的因素决定游戏得分，导致分数增长与记忆保持脱钩；无限时长模式下，分数本质上正比于游戏时长，排行榜成为耐力竞赛而非能力竞赛；客户端上报成绩又给了刷分空间。
- **解决思路**：① 使游戏得分完全由学习相关指标（逐词得分比、速度、准确率）决定，游戏输赢与记忆能力同构；② 设置限时模式并使"剩余生命"与"得分"形成权衡，约束无止境累积；③ 服务端依据逐词日志重算成绩，开局快照固化词池与章节集合，结算回写分组，杜绝伪造；④ 排行榜按"词库 + 章节集合 + 模式 + 难度"分组，组合选择相同者才同榜，保障公平性。
- **预期结果**：游戏分数成为记忆能力与输入熟练度的可信度量；排行榜排名反映真实的相对能力差异，而非时长或运气。

**问题五：教学组织过程中的考核公平性与过程真实性难以保障。**
- **问题描述**：线上考核存在切屏抄袭、多人共用同一套试卷泄题、中断续考反复重试刷分等风险；此外限时干预若与计分耦合，会导致不同限时设置下的成绩不可比，污染难度测量。
- **解决思路**：① 考核模板在生成时即固化试卷（全员同卷），交卷时随卷下发模板卷而不返回答题内容，从源头阻断泄题；② 强制全屏作答 + 双通道失焦检测（窗口失焦与页面隐藏）+ 回合去重 + 自愈窗口，并将失焦计数写入成绩记录；③ 幂等交卷与中断作废机制阻断网络重试刷分；④ 计分权重与限时档位解耦，保证跨档位可比；⑤ 管理端提供题目级与知识点级的掌握度统计。
- **预期结果**：考核结果的过程可信度可追溯；不同限时设置下的成绩具有横向可比性。

**问题六：单机部署架构下的数据可靠性与并发正确性风险。**
- **问题描述**：SQLite 在单机部署下需规避多写者竞争；网络重试、页面刷新、并发作答等均可能导致重复写入与数据不一致；客户端提供的键入耗时等数据不可信，需服务端复核；数据备份若采用文件复制方式在数据库运行期可能得到不完整的快照。
- **解决思路**：① 采用 WAL 模式的 SQLite 并保持单进程单写者；② 建立统一幂等中心（键 + 端点 + 状态码 + 响应快照，24 小时去重）与单题 `request_id` 体幂等；③ 对速度数据设定有效性阈值与上限过滤（如 < 300 毫秒视为误触无效、上限 250 WPM），杜绝瞬时异常值；④ 备份采用 SQLite 原生备份 API 而非文件复制；⑤ 定时任务统一调度（备份、清理、统计重算），并保证不重复触发。
- **预期结果**：在单机架构下实现数据一致性与可恢复性；异常上报数据不会污染统计口径。

### 3.5 预期创新点

1. **反馈粒度的分场景设计**：学习场景保留模糊反馈（容错 + "近似"档）与考核场景采用连续得分比（严格量化），在同一系统中实现两类反馈的并存与对照，为"反馈粒度如何影响记忆效果"提供了可实证的研究载体。
2. **打字动作与记忆巩固的行为耦合**：以"能准确快速地敲出该词"作为记忆巩固的行为标志，把输入技能训练嵌入记忆学习流程，实现技能训练与记忆训练的双向增益。
3. **队列全量物化 + 三层优先级的调度实现**：以"逾期 / 高危 / 巩固"显式分层替代每日定时跑批，实现幂等可重入、可解释、可预测的复习调度。
4. **跨语言判定一致性的工程保障机制**：对拍脚本 + 单一口径入口 + 双端逐位等价复刻，将"隐性口径漂移"这一易发难察的缺陷转化为可自动拦截的构建失败。
5. **过程性数据的采集—度量—干预闭环**：从按键日志到学习建议的完整链路，使过程性数据真正参与学习干预，而非仅作统计展示。

### 3.6 技术路线与可行性

- **技术栈**：前端采用 Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus，游戏引擎使用原生 Canvas 实现实时渲染；后端采用 FastAPI + SQLAlchemy（异步）+ SQLite（WAL）+ APScheduler + JWT + bcrypt；部署采用 Nginx 反向代理 + systemd 守护的单机架构，并配套定时备份与日志轮转。
- **架构分层**：路由层（API）→ 服务编排层（Service）→ 数据访问隔离层（Repository）→ 纯算法层（Domain）。算法层全部为无副作用纯函数，使判定与调度逻辑可独立测试。
- **可行性依据**：系统已完成完整实现并在真实服务器环境上线运行，各业务模块、算法口径与数据模型均经过生产环境验证，本设计的工作重点在于方法的规范表述、效果的对照性验证与理论归纳，而非从零开发。
