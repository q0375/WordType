# 三、论文（设计）提纲

> **文档性质**：本文给出毕业论文的完整章节提纲（含三级标题）、各章写作要点与字数配比、图表规划，以及可直接复用的项目资产对应表。
>
> **核心原则**：提纲不是"通用模板套项目"，而是**以项目已形成的文档体系为骨架反向组织**。本系统已完成需求规格说明书、数据库设计文档、系统架构设计文档、接口规范、UI 规范、流程图集、口径总纲共七份设计文档，论文提纲即由此映射而来——这意味着论文写作阶段的主要工作是**重组与提炼已有材料**，而非从零撰写，可显著降低写作风险与周期。

## 3.1 论文总体结构与字数配比

**建议总字数：3.2 万～4.0 万字**（不含附录与代码清单；按学校具体要求调整）

| 部分 | 章次 | 建议字数 | 占比 | 主要来源 |
|---|---|---|---|---|
| 前置部分 | 摘要（中英文）、目录、图表清单 | 1500 | 4% | 论文完成后提炼 |
| 第一部分 | 第 1 章 绪论 | 3500 | 10% | 已完成的开题报告 + 文献台账 |
| 第二部分 | 第 2 章 相关理论与关键技术基础 | 4000 | 12% | 文献台账 + 口径总纲 |
| 第三部分 | 第 3 章 系统需求分析 | 4500 | 13% | 需求规格说明书（D1–D34）+ 产品体验评估报告 |
| 第四部分 | 第 4 章 系统设计 | 8000 | 22% | 架构设计文档 + 数据库设计文档 + 接口规范 + UI 规范 + 流程图集 |
| 第五部分 | 第 5 章 系统实现 | 9000 | 25% | 源代码 + 七个对拍校验脚本 + 测试报告 |
| 第六部分 | 第 6 章 系统测试与效果分析 | 6000 | 17% | 测试报告 + 过程性数据 + 对照实验（若执行） |
| 第七部分 | 第 7 章 总结与展望 | 1800 | 5% | 全文归纳 |
| 后置部分 | 参考文献、致谢、附录 | 2000 | 6% | 文献台账 |

> **配比说明**：本科毕业设计的常见问题是"设计写得很厚、实现写得很薄"。本提纲将第 5 章（实现）与第 4 章（设计）配比设为 9:8，并明确要求实现章节以"关键机制的实现"而非"代码罗列"为主——这是判定论文质量的关键分水岭。

## 3.2 完整章节提纲

### 前置部分

- **中文摘要**（400～600 字）：研究背景一句话 → 核心问题一句话 → 系统方案一句话 → 关键实现机制两到三句 → 主要工作与结论一句话。**必须包含定量结论**（如"支撑 9 类业务模块、22 个数据表、七项一致性校验"），避免纯定性描述。
- **关键词**：间隔重复；提取练习；打字练习；助记系统；一致性校验
- **英文摘要**：与中文摘要内容严格对应，术语采用国际通用表述（Spaced Repetition; Retrieval Practice; Typing Practice; Mnemonic System; Consistency Verification）。
- **图表清单**：按类别（表/图）分别自动生成，编号连续。
- **目录**：自动生成，须三级标题。

## 3.6 图表与写作规范提示

1. **正文中每一处设计决策，都应能回答"为什么这样定"**。若某处只是"这样实现了"，则说明设计论证尚未完成；
2. **量化优于定性**。"响应速度快"不如"接口在 100 并发下零失败，单连接吞吐受带宽限制"；
3. **约束与代价必须同时写**。每个技术选择都写清代价，可信度远高于只讲优势；
4. **诚实面对局限**。承认样本量小、对比非受控实验、部分结论属设想，比掩盖它们更有说服力——**答辩中"我不知道，这是我的局限，也是我下一步的工作"是安全的回答，而强行辩解是危险的**；
5. **图与文一致**。所有流程图、架构图必须与最终代码一致，不存在"文档画得比代码美好"的情况。
