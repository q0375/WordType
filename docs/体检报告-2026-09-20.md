## 二、🔴 高危

### H1. 登录失败锁定完全失效（可无限暴力破解）

- **位置**：`backend/app/services/auth_service.py:83-92`
- **证据**：第 87 行 `ratelimit.login_failed(username, ip)` 的**返回值被丢弃**，全仓库没有任何地方检查「是否已达锁定」。
  `backend/app/core/ratelimit.py` 的模块说明却写着「登录失败锁定（用户名+IP，5 次/10min）」，README 也宣称有锁定。仅注册接口真正消费了限流（`register_allowed`）。
- **实证**：对 admin 连打 8 次错误密码 → 全部 `401`；第 9 次用**正确**密码 → `200` 并签发 token。
- **影响**：登录接口可无限次尝试，口令爆破无任何阻碍；对 admin 这种高价值账号尤其危险。
- **建议**：`login()` 入口先判定 `login_allowed(username, ip)`，超限抛 `RATE_LIMITED`（注意保持响应不可区分以防用户名枚举）；登录成功时清空该 key 的计数。

### H2. `letter_stat` 夜间聚合任务长期失败（静默）

- **位置**：`backend/app/tasks/scheduler.py:56-108`（尤其是 **96-103 行的缩进**）
- **证据 1（缩进错误）**：水位线 upsert 块被写在 `for r in records:` 循环体**内部**。一次运行对同一主键 `letterstat_watermark` 执行 N 次 `db.add()`；下一次 SELECT 触发 autoflush 时 → `UNIQUE constraint failed: system_setting.key` → 整个事务回滚 → 任务失败，水位线永不落库。
- **证据 2（`json` 后置导入）**：第 63 行使用 `json.loads`，而 `import json` 在第 69 行（函数内、且在**使用之后**），模块顶部也没有导入 json。一旦水位线行存在，第二次运行即 `NameError`。
- **实证**：
  - `backend/data/uvicorn.log`：`2026-09-19 04:00:00 ERROR letter_stat failed: ... UNIQUE constraint failed: system_setting.key`
  - 在数据库副本上复现，SQLAlchemy 报出 **82 组**重复的 `INSERT INTO system_setting ('letterstat_watermark', '505', ...)`。
- **影响**：字母/指法统计 `letter_stat` 停止更新 → 仪表盘「指法专项：字母组合 cg、mr、vh…」类建议基于陈旧数据；`system_setting` 里至今没有 `letterstat_watermark` 行。
- **建议**：把 96-103 行**移出 for 循环**（循环结束后做一次 upsert）；`import json` 提到模块顶部。

### H3. 注销「30 天后物理清理」并不存在（隐私承诺未兑现）

- **位置**：前端 `frontend/src/views/profile/ProfileView.vue:44`、`:111`（文案）；后端 `backend/app/tasks/scheduler.py:143-150`（任务注册）
- **证据**：UI 明确写「注销为软删除，**30 天后定时任务物理清理**（含私有词库与全部统计）」「注销后 30 天内可联系管理员恢复，到期物理删除全部数据」。但 `start_scheduler()` 只注册了 `backup / cleanup / letterstat` 三个任务，`job_cleanup()` 内没有任何 user 行的物理删除；全仓库检索不到硬删 user 的代码（`admin_service.py:115` 只有「恢复窗口」判定，无反向删除）。
- **影响**：用户以为数据会到期删除，实际**永久保留**；属于对外承诺与实现不一致（合规风险）。
- **建议**：二选一——(a) 实现 purge 任务：删除 `is_deleted=1` 且注销超过 30 天的 user 行，并**级联清空全部关联表**（含私有词库及其章节/单词）；(b) 修改 UI 文案为「软删除保留」。

### H4. 导出 CSV 的中文文件名丢失

- **位置**：`backend/app/api/v1/endpoints/books.py:55-59`
- **证据**：`filename*` 用了 `filename.encode('ascii','ignore').decode() or 'export.csv'`。纯中文名被 ascii 过滤后**只剩扩展名 `.csv`**（非空字符串），因此 `or` 兜底永远不会触发。实测响应头：
  `Content-Disposition: attachment; filename*=UTF-8''.csv`
- **影响**：浏览器把文件存成无名 `.csv`；用户无法分辨导出的是哪个词库。
- **建议**：`filename*=UTF-8''{urllib.parse.quote(filename)}`（RFC 5987 要求百分号编码），另加一个 ASCII 兜底参数 `filename="export.csv"`。

## 三、🟡 中等

### M1. `daily_activity` 31 行孤儿数据会被新用户继承

- **现状**：`daily_activity` 中 `user_id` 为 64–94 的 31 行**没有对应用户**（`user` 表 `MAX(id)=54`）。
- **机制**：所有统计查询都只按 `user_id` 过滤、**不 JOIN user**（如 `misc_service.py:84/90/112/429`）；SQLite 的行 id 复用为 `MAX(id)+1`，因此当用户量增长到该区间时，新注册用户会**直接看到前一位用户的打卡/热力图**。
- **实证**：此前的复现中，新注册用户拿到 `id=64` 后，仪表盘热力图立刻显示「2026-09-19 正确 24」。
- **建议**：① 清掉这 31 行孤儿；② 从根上杜绝——id 不复用（`AUTOINCREMENT`，或软删用户永不硬删）；③ 统计查询加 `EXISTS(user)` 保护。

### M2. 匿名 `/tts` 无鉴权且无频率限制

- **位置**：`backend/app/api/v1/endpoints/misc.py:18-21`（注释说明 `<audio>` 无法携带 Authorization 头，属有意设计）
- **实证**：无 token 访问 `/tts?word=hello` → `200`；连续 25 次不同词 → **全部 200**，无限流。长度上限有效（`word=200 字符` → 422）。
- **风险**：每次匿名请求都会触发一次微软 edge-tts 上游调用并写入 `data/tts_cache`。缓存**没有容量/条目上限**（`_locks` 字典也随唯一词无界增长），可被批量请求填满磁盘并消耗上游配额。
- **建议**：复用 `core/ratelimit` 给 `/tts` 加 IP 限流；缓存加 LRU/条目上限（如 5 万条）。

### M3. 修改密码没有强度校验（注册有，改密没有）

- **位置**：`backend/app/schemas/__init__.py:35-37`（`PasswordIn.new_password` 仅 `min_length=8`）对比 `:20-26`（`RegisterIn.password` 额外要求「同时包含字母与数字」）
- **影响**：用户可把密码改成 `12345678` 或 `aaaaaaaa`，绕过注册时的强度要求。
- **建议**：抽一个共享的 password 校验器，两个 schema 复用。

### M4. 前端主包 1.2 MB（Element Plus 全量 + 全量图标全局注册）

- **位置**：`frontend/src/main.ts:4,10-13`（`app.use(ElementPlus)` + 遍历 `ElementPlusIconsVue` 注册**全部**图标）
- **实测产物**：`dist/assets/index-*.js` = **1,201,085 B**；`index-*.css` = 343 KB。（`vite.config.ts` 的 `chunkSizeWarningLimit` 已被抬到 900 KB）
- **影响**：这是**手机优先**的学习应用，4G 下首屏下载 + 解析明显偏慢。
- **建议**：引入 `unplugin-vue-components` + `ElementPlusResolver` 按需注册组件与样式；图标改为按名显式导入（项目实际只用到几十个）。通常可砍掉主包 50%–70%。
