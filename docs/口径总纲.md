## 1. 时限

考核与游戏各有一套时限，**语义独立、数值目前相同但可分别调整**。

| 场景 | 公式 | 可配 | 实现 |
|---|---|---|---|
| 考核·打字题（默写/挖空/听音） | 倒计时 `ceil((5 + 0.75 × 字符数) × 档位倍数)` | 档位三选一（2026-09-21 恢复）；倍数写死 | `domain/exam_timing.py` |
| 考核·选择题（四选一） | 倒计时 `ceil(10 × 档位倍数)` | 同上 | 同上 |
| 游戏·单词时限（计分权重） | `ceil(字母数 ÷ 3 ÷ 难度系数)`，下限 2s | ❌ 写死 | `domain/game_score.py` + `core/gameRules.ts` |

- **限时档位**（组卷时三选一，`ExamStartIn` / `ExamTemplateIn.time_policy`）：
  宽松 `relaxed ×1.5` / 标准 `standard ×1.0` / 紧凑 `tight ×0.7`（`defaults.EXAM_TIME_POLICIES`，写死不再做管理端可配）。
  **只作用于每题倒计时**——计分权重恒用原始时限，选哪档卷面分公式不变（用户定稿 2026-09-21）。
  倍数由后端算好下发（`payload.limit_s`），前端不参与倍数计算。
- **难度系数**（写死在代码）：简单 0.8 / 普通 1.0 / 困难 1.25（2026-09-19 改）
- 单题时限下限：考核 3s（向上取整）、游戏 2s
- **游戏下坠时长 ≠ 时限**（2026-09-20 改）：局面常有多词同屏，按时限直落太快——
  下坠（出现 → 消失）= `时限 × 下坠倍数`（`core/gameRules.ts::fallDurationSeconds`，仅前端动画；计分权重仍是时限本身，后端无感）。
  **下坠倍数是全局唯一可配口径项**：`system_setting.game_fall_duration_mult`，默认 2、范围 1~10（步进 0.5），
  管理端「游戏节奏」对话框修改（`PUT /admin/game-config/fall-mult`），随 `/settings` 下发，保存即时生效
- **倒计时与权重分离**：每题同时下发 `base_limit_s`（原始时限＝**计分权重**）与
  `limit_s = ceil(base_limit_s × 档位倍数)`（实际倒计时）。
  权重不受档位影响；标准档（×1.0）下两者数值相同。

### 词库「限时秒」（`word.time_limit_s`）的完整语义

四条缺一不可，历史上多次踩坑：

1. 只作用于**考核打字题**（默写 / 挖空 / 听音）
2. 替换公式里的基准值（最终倒计时 = `ceil(该值 × 档位倍数)`）
3. 对**考核选择题无效**（选择题固定 10s 基准）
4. **不参与游戏**下坠与计分（2026-09-19 起彻底移除游戏侧消费）

## 2. 计分

### 考核卷面分

```
得分比 = 序列相似度 difflib.SequenceMatcher(a, b).ratio()
                                     （2026-09-20 换算法；连续值 0~1，大小写敏感、空格等一切字符参与比较）
卷面分 = Σ(得分比 × 该题原始时限) ÷ Σ(该题原始时限) × 100
```

- 得分比**不再是三档**（正确/近似/错误）：2026-09-19 改连续值；2026-09-20 起算法为序列相似度（difflib），管理端不可配
- 权重用**原始时限** `base_limit_s`（不含档位倍数）：无论组卷选宽松 / 标准 / 紧凑，卷面分不变——档位只影响每题倒计时（用户定稿 2026-09-21）

- `ExamRecord.score` 存四舍五入后的整数，精确小数在 `detail_json.score_exact`

### 游戏单词得分

```
得分比 = 序列相似度 difflib.SequenceMatcher(a, b).ratio()   （同考核，core/judge.partialRatio）
单词得分 = ceil(得分比 × 该词落地时限 × Combo 倍率)
```

- 落地时限（计分权重）= `ceil(字母数 ÷ 3 ÷ 难度系数)`；**得分不再乘 10**（2026-09-19 改）
- **下坠时长 = 时限 × 下坠倍数**（2026-09-20 改）：多词同屏按原时限直落太快，默认放缓一倍；
  倍数管理员全局可配（1~10，默认 2）；仅影响动画节奏，得分、掉血、Combo 均不变，后端仍按时限复核
- 得分比是纯计算的序列相似度（与考核同源同算法），无任何可配项

- Combo 阶梯：连击 5 → ×1.5、10 → ×2.0、15 → ×2.5、20 → ×3.0（上限）
- 计入 Combo：整词销毁（含「近似」销毁）
- 清零 Combo（倍率按 1.0）：触线落地、整词敲错弹回、中途放弃（Delete / Shift+退格）
- 部分分 = 已输入正确字符数 ÷ 总字符数（大小写敏感）——**与整词得分比是同一个公式**
- 服务端复核：`recompute_score`，客户端分数偏差 > 5% 时以服务端为准
- 血条：上限 500 点（`GAME_HP_MAX`），掉血 = `round((1 - 得分比) × 100)`（`GAME_HP_DAMAGE_UNIT`，半进位），
  满分不掉血；扣减仍在前端实时表现，**服务端结算时按词日志同步重算**（`hp_damage`，2026-09-21 起参与复核）
- **生命奖励**（2026-09-21 新增，用户定稿）：**限时模式**到时结算时，剩余生命 1:1 计入总得分——
  服务端重算剩余生命（500 − Σ 掉血）后加进 `final_score`，响应带 `hp_bonus` 供结算页展示；
  仅 `mode=timed` 且有效时长 ≥ 180s（`GAME_TIMED_LIMIT_MS`）才给：中途退出未到时不给，
  血尽剩余 0 自然无奖励；奖励计入成绩与排行榜（`is_new_record` 按含奖励总分判定）
- **漏词扣分**（2026-09-20 新增，前后端同式 `fall_penalty`）：词触红线在部分分之外
  另扣 `ceil((1 - 得分比) × 时限)`——没碰的词扣 `ceil(时限)` 分（2~5 分，≈一个完美词的得分）；
  中途放弃（Delete / Shift+退格）**不扣分**（仍只扣血 + 部分分）。落地浮层红色「−N」提示

### 跨模块耦合（2026-09-19 已消除）

旧口径里 `exam_score_ratios` 同时服务考核与游戏，改一处两端都变。
**现在得分比是纯计算的序列相似度（双端 difflib 同源），不再有任何配置**，耦合随之消失。

## 3. 宽松度（判定）

判定引擎双端同源：`domain/judge.py` ↔ `core/judge.ts`。
结果三档：`correct` / `near` / `wrong`，由 Levenshtein 距离与容差比较得出。

**基线规则**：`normalize` 仅去首尾空白，**大小写敏感**——
`"Apple" ≠ "apple"`，首字母大写判 near（差 1 个字符），全大写判 wrong。

容差：

| 模块 | 容差 | 可配 |
|---|---|---|
| 学习 / 练习 / 复习 | **固定 1**（差 1 个字符判 near） | ❌ 无开关（2026-09-20 取消） |
| 考核 / 游戏 | 不判 near——**直接按序列相似度连续计分** | — |

### 用户可见反馈统一展示得分比（2026-09-21）

`correct / near / wrong` 三档**仍用于内部调度**（SM2 熟练度质量、错题本、重现队列），但
**界面反馈不再展示「近似正确（差一个字母）/ 答错」两套话术**——与连续得分比口径冲突
（编辑距离是绝对值、得分比是相对值，同样 0.85+ 的相似度可能一边"只差一点"一边"答错"）。
现在学习默写与练习打字题的反馈在不完全正确时**一律展示「不完全正确（得分比 X%）」**
（`/study/dictation` 与 `/practice/answer` 响应新增 `ratio` 字段，difflib 同源值）；
四选一仍非对即错，维持「答错 ✘」。

### 宽松度已无任何开关（2026-09-20）

判定行为全部固化：设置页不再有「宽松判定」开关，`PUT /settings` 也不再接受 `loose_match`。

> **已移除清单（2026-09-19 ~ 09-20）**：卷内 `loose_match`、用户设置 `loose_match` / `exam_loose_match`、
> 管理端 `exam_tolerance_rules` 分级容差、`exam_score_ratios` 得分比、`exam_time_factors` 每词限时倍数，
> 连同 `/exam/policy`、`/admin/exam-config`、`/admin/exam-config/{time-factors,score-ratios,tolerance-rules}`
> 全部端点。数据库里若残留 `exam_*` 配置行属死数据，可安全清理
> （`user_settings.loose_match` / `exam_loose_match` 列保留但已弃用）。

## 4. 难度

**「难度」在两个模块是两套不同的东西**，只是首档数值接近，极易混淆：

| 模块 | 名称 | 值 | 存储 | 影响 |
|---|---|---|---|---|
| 游戏 | 简单 / 普通 / 困难 | 0.8 / 1.0 / 1.25 | **写死在代码** | 单题下坠时限（时限 = 词长÷3÷系数） |
| 考核 | 宽松 / 标准 / 紧凑（限时档位） | ×1.5 / ×1.0 / ×0.7 | 写死（`defaults.EXAM_TIME_POLICIES`，2026-09-21 恢复） | 每题倒计时（**不影响计分**） |

> 考核档位组卷时三选一、随卷快照固化；游戏难度开局时选择。两者语义独立，数值接近纯属巧合。

游戏难度还额外影响画面节奏（`core/gameRules.ts` 的 `DIFF`）：
初始下落速度、加速度、同屏词数上限、生成间隔。
它与 `FALL_DIFF_FACTOR`（时限系数）是**两个维度**，不要混为一谈。

管理端**没有**游戏难度配置入口（设计如此）。

## 5. 覆盖优先级

考核参数有多个来源，优先级从高到低：

1. **管理端下发的卷**（`exam_template` 组卷快照）
2. **学生自组卷**时表单填写的值
3. **用户设置页**的默认值（`exam_time_limit` / `exam_pass_score`）
4. **系统默认**（`domain/defaults.py`）

> 已下发的卷使用组卷时的快照。口径已全部固化，当前不存在可修改的全局口径项；
> 若将来新增可配项，仍遵守「只对新组卷 / 新交卷生效」的原则。

## 7. 改动检查清单

改任何口径，按序执行：

1. **改常量**
   - 后端 → `backend/app/domain/defaults.py`
   - 前端 → `frontend/src/core/gameRules.ts`（游戏）或 `core/judge.ts`（判定）
   - **两端都要改**，跨语言无法自动同步
2. **跑对拍**
   - 判定相关 → `.workbuddy/tools/judge_sync/verify_judge_boundary.py`（182 条边界矩阵双端对拍，改口径必跑）
   - 口径隔离 → `.workbuddy/tools/judge_sync/verify_judge_scope.py`（残留清查 + 常量唯一来源 + 只读/权限）
   - 大小写与计分 → `.workbuddy/tools/judge_sync/verify_case_sensitive.py`（游戏/练习/考核真实 API + 卷面分公式）
   - 游戏时限 → `.workbuddy/tools/game_sync/verify_limit_difficulty.py`（42 条双端对拍 + 8 条语义）
   - 游戏时限（真实交卷）→ `.workbuddy/tools/game_sync/verify_limit_difficulty_api.py`
   - 游戏计分 → `.workbuddy/tools/game_sync/verify_game_rules.py`（公式单测 + 真实 API 复核）
   - UI 口径 → `.workbuddy/tools/judge_sync/verify_judge_ui.py`（设置页/控制台对话框/游戏浮层）
3. **改 UI 文案**：管理端 hint、游戏页说明、设置页说明同步更新，**不要写死数字**（从接口读）
4. **重建前端**：`cd frontend && npm run build`
5. **改 models 需迁移**：`models.py` 变更必须在 `db/init_db.py` 补对应迁移
6. **上线**：走 `deploy/deploy.sh`（只同步 `app/`、`scripts/`、`requirements.txt`、前端 dist，
   **永不触碰** `data/`、`backup/`、`.env`、venv）

## 7.5 错题本归属规则（2026-10-03）

错题本只收「**真的答错了**」的词，以下三类**不进**错题本（其余统计口径不变）：

| 情形 | 判定依据 | 处理 |
|---|---|---|
| 考核提前交卷/放弃时**未作答**的题 | 该 qid 不在提交的 answers 里 | 成绩按 0 分计、stat/daily 照旧，**不写错题本** |
| 游戏**主动放弃**当前单词（Delete / Shift+Backspace） | `destroyed=false 且 landed=false` | 扣分掉血照旧，**不写错题本** |
| 学习/练习/听写**中途结束**的未作答题 | 从不提交，服务端无记录 | 天然不产生错题本 |

仍在计入的：考核已作答但答错、游戏**触线落地**（`landed=true`）、学习自评「不认识」、练习/复习/游戏真实答错。

**已攻克（连对 3 次移出）之后再答错**：重新计入错题本，并把 `conquer_count` 归零、`resolved` 置回 0、
刷新 `added_at` —— 即「攻克不是永久免疫，再错就重新练」，与熟练度 p≥80 掌握退出是同一套回退哲学。

## 7.6 练习「例句挖空」与建议直达（2026-10-04）

### 例句挖空（cloze）显示与空态

- **显示**：英文挖空句一行（Georgia 斜体）+ **中文释义一行**（非斜体、弱化色）。释义取 `word.meaning`，即默写题用的那个权威字段。
- **出题条件**：词的 `example` 非空**且例句中含该词**（大小写不敏感）。全库 33.9 万词仅 1.57 万有例句，其中 96% 例句含本词 —— 所以**按章节勾「例句挖空」很可能一题都出不来**，这是正常状态而非故障。
- **空态口径**（原为整页空白，属 bug）：
  - 勾了但一题都出不来 → 响应带 `skipped:[{type,reason:"no_example"}]`，前端 toast 提示「所选范围内没有可用的例句挖空题，换个章节或取消勾选『例句挖空』」，**其余题型照常出题**。
  - 全部勾选题型都无题 → 后端 `400 EMPTY_QUESTION_POOL`，**不返回空题组**（返回空数组会让 `running=true` 而 `current=null`，模板不渲染 → 白屏）。
  - 前端再加一道兜底：`questions.length===0` 不进答题态，留在配置页。

### 仪表盘「去执行」落地页

`action.type` → 落地页一一对应，**没有对应模块的建议不给按钮**（不制造假入口）：

| action.type | 落地 | 说明 |
|---|---|---|
| `books` | `/books` | |
| `review` | `/review` | |
| `study_plan` | `/study` | |
| `practice` + `word_ids` | `/practice?word_ids=…` | 带上那批高错误率词**跳过章节选择直接开跑**，题头标「来自『今日建议』的专项练习」；进页后立刻 `router.replace` 清 query（防刷新/keep-alive 重入重复开组），故 ids 须快照进普通 ref 再用 |
| `typing_drill` | **无** | 系统没有「指法训练」模块，`letter_stat` 只用于生成建议文案 → 隐藏按钮 |
| `none` / 未知 | **无** | 同上 |

⚠️ 旧 bug 记录：`actionRoute` 曾拿 `action.type` 去比 `'high_error'`（那是 **item.type**），永不命中 → 所有建议靠兜底跳 `/practice`，两条不同建议落在同一页，且 `params.word_ids` 被整个丢弃。

## 8. 澄清几个常见误解

| 误解 | 实际情况 |
|---|---|
| 调游戏难度能让词落慢点 | 游戏难度系数写死（0.8 / 1.0 / 1.25），只能改代码；管理端已无考核限时**倍数**可调（档位三选一随卷固化） |
| 考核有「宽松判定」开关可调松紧 | 已取消；考核按序列相似度连续计分，没有开关也没有容差配置 |

### 临时账号约定（2026-09-20 起）

API / UI 级脚本统一走 `.workbuddy/tools/verify_common.py` 的 `ensure_user()`：

- **固定用户名 + 登录优先**（`vt_case` / `vt_scope` / `vt_ui` / `vt_lvdiff`），账号跨运行复用。
  早期脚本每次运行都用 uuid 注册新号，而 `/auth/register` 有「每 IP 10 次/小时」限流，
  连续跑第二遍就整片 429、表现为脚本自身报错 → 已全部改造。
- 注册被限流时，`ensure_user()` 会**直接落库预置等价账号**（同样的 bcrypt 哈希 + 默认设置行），
  保证脚本始终可重复运行。
- 结束时 `purge_user_data()` **只清数据行、保留账号**，因此下次运行无需再注册；
  残留断言由「user 行数 == 0」改为「残留数据行 == 0」。
- 这批账号是一次性夹具，若需彻底移除：删其数据行后再删 user 行即可。
